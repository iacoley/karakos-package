# AGENTS.md — start here

Karakos is a self-hosted, multi-agent household assistant powered by the Claude
Code CLI. One Docker container runs four supervised processes (`bin/agent-server.py`,
`bin/relay.py`, `bin/scheduler.py`, the Next.js dashboard); agents are `claude`
subprocesses managed by the agent server. Upstream: `mcarmody/karakos-package`.

Operating, repairing or contributing to an install: read
[docs/AGENT_GUIDE.md](docs/AGENT_GUIDE.md) next. How it works: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Layout (who owns what)

| Path | Owns |
|---|---|
| `bin/` | Entry points. `agent-server.py` (queue, subprocesses, HTTP API, cost guard), `relay.py` (Discord), `scheduler.py` (timers), `entrypoint.sh`, `karakos` (host migrate wrapper), `preflight.sh`, `create-agent.sh`, `buildq`, `self-upgrade.sh` (container side of the Docker self-upgrade), `upgrade-agent.sh` (its host-side cron half; `make install-upgrade-agent`) |
| `lib/` | Importable logic: `registry.py` (agents.yaml), `outbox.py` (Discord delivery), `graph/` (memory), `migrate/` (schema migrator), `stall.py`, `setup_answers.py` |
| `mcp/` | MCP tool servers (`tools-server.py` discovers `skills/`) |
| `skills/` | Agent tools: `skills/<name>/tools.json` + `scripts/` (not Claude Code's `SKILL.md` feature) |
| `agents/` | `templates/*.md` (primary, monitor, builder, reviewer, shard, onboarding), `CORE.md`, `HOUSE_STYLE.md`; per-agent dirs are created by setup |
| `config/` | Compose file, `hooks.json`, `protected-paths.json`, `supervisord.conf`, `.env.template`; `.env`, `agents.yaml`, `channels.json` are generated by setup (only `.env` is git-ignored) |
| `system/` | Safety hooks (`system/hooks/`), `check-protected-paths.py`, `check-secrets.py`, `check-coupling.sh` |
| `dashboard/` | Next.js app with its own `package.json` (`npm ci && npm test`) |
| `tests/` | pytest suite; `tests/harness/` runs the real agent server against a fake `claude` |
| `docs/` | Operator and contributor docs; `tests/test_docs.py` checks them against the code |

## Tests

Run only what you touched. Docker is not needed for the default selection.

```bash
pip install -r requirements.txt pytest
python3 -m pytest tests/test_setup.py -q               # one file
python3 -m pytest tests -m "not slow" -q               # what the CI unit job runs
python3 -m pytest tests/test_docs.py -q                # after any docs/ or README change
bash system/check-coupling.sh                          # must print "coupling: clean"
```

Markers (`pytest.ini`): `slow` = needs Docker or the real CLI (deselect with `-m "not slow"`);
`docker` = needs a Docker daemon (skipped when absent unless `KARAKOS_REQUIRE_DOCKER=1`);
`realcli` = calls the real `claude` CLI, spends tokens, needs a credential
(`python3 -m pytest tests -q -m "slow and realcli"`). Some harness tests time out under
full-suite load and pass alone.

## Branches

- **`develop`** is the integration branch. Every PR targets it (`gh pr create --base develop`). GitHub's default branch may still read `main`, so never rely on the default.
- **`main`** is releases only. It changes through a release PR from `develop` that the maintainer approves. Installers clone `main`.
- Same-repo PRs into `develop` auto-merge (squash) once the required checks pass (`.github/workflows/auto-merge.yml`). Open a PR as draft to hold it.
- Both have rulesets: PR required; checks `lint-and-syntax`, `unit-tests`, `docker-smoke` required; no force-push, no deletion.
- Branch off `develop`, one logical change per PR, fill in `.github/pull_request_template.md`. Never push to `main` or `develop`.
- Process and release steps: [CONTRIBUTING.md](CONTRIBUTING.md).

## Protected paths

`config/protected-paths.json`, enforced by a git pre-commit hook (`system/install-hooks.sh`,
installed by `bin/entrypoint.sh` into the container workspace only: a clone on the host is not
blocked, so PR review is the gate there). They guard process lifecycle,
safety hooks and secrets, so an agent cannot edit the rules that constrain it.

- **Tier 1, blocked:** `system/`, `config/`, `.karakos/`, `Dockerfile`, `bin/agent-server.py`,
  `bin/relay.py`, `bin/entrypoint.sh`, `bin/scheduler.py`, `bin/hooks-sync.py`.
- **Tier 2, review required:** the rest of `bin/`, `agents/templates/`, `agents/CORE.md`,
  `agents/HOUSE_STYLE.md`, `mcp/tools-server.py`.
- Always writable: `agents/*/persona/`, `agents/*/journal/`, `agents/*/inbox/`.

If a commit is blocked on a tier 1 path, stop and report the path to the maintainer. Do not
work around the hook (no `--no-verify`, no editing `config/protected-paths.json`).

## Conventions a newcomer misses

- The compose file is `config/docker-compose.yml`, not at the root. Use `make` (`make help`) or
  `docker compose -f config/docker-compose.yml --env-file config/.env`. The one service is `karakos`.
- Only `config/`, `agents/` and `.karakos/` are bind-mounted from the checkout. `bin/`, `lib/` and
  the rest are baked into the image: editing the checkout does not change a running container
  (`make pull` for a release, the dev override in `docs/EXTENDING.md` to test your own change).
- `setup.sh` generates `config/.env`, `config/agents.yaml`, `config/channels.json`. Never commit them
  or any token; stage files by name, not `git add -A`. `system/check-secrets.py` runs in the pre-commit hook.
- No household identifiers (names, hostnames, IPs, Discord IDs, home paths) in tracked files;
  `system/check-coupling.sh` enforces it in CI. Use neutral ids like `main`, `helper`, `builder`.
- Runtime state is keyed by shard id. Existing data is changed only by `lib/migrate/steps/`, never at boot.
- Docs are tested: a backticked repo path that does not exist, a documented env var no code reads, or a bad
  `bash` block fails `tests/test_docs.py`.
- On a small host, heavy local builds (`tsc`, `next build`, `npm ci`) can be blocked by
  `system/hooks/block-heavy-build.py` (`heavy_build_block` in `config/hooks.json`, off by default).
  CI is the authority for the dashboard build and `docker-smoke`.
- Unattended install: `./setup.sh --answers answers.json` ([docs/answers.example.json](docs/answers.example.json)).
